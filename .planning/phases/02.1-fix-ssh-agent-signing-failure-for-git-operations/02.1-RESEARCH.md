## Summary

This phase fixes the git commit signing failure when using SSH agent forwarding from NixOS to macOS (1Password SSH agent). Phase 2 configured `ssh-keygen` as the signer, but the signing fails because the current configuration doesn't properly handle how git invokes `ssh-keygen -Y sign`.

The core issue is understanding how git passes parameters to the signing program and ensuring `ssh-keygen` can locate the private key via `SSH_AUTH_SOCK`.

**Primary recommendation:** Configure git to use `ssh-keygen` directly with proper `gpg.ssh.allowedSignersFile` setup; git automatically passes the correct namespace (`git`) and key file to `ssh-keygen -Y sign`.

## Architecture Patterns

### How Git SSH Signing Works

Git invokes the signing program (`gpg.ssh.program`) with the following protocol:

```
ssh-keygen -Y sign -f <key_file> -n git < data_to_sign
```

The key parameters:
- `-Y sign`: Use signature mode (not key generation)
- `-f <key_file>`: Path to public key file (e.g., `~/.ssh/id_ed25519.pub`)
- `-n git`: Namespace is "git" (prevents signature confusion across domains)
- Input: Data to sign via stdin
- Output: Signature written to `<file>.sig` or stdout

**Source:** [ssh-keygen man page](https://man.openbsd.org/ssh-keygen#Y_sign)

### Key Discovery for SSH Agent

When the private key is not in a file but available via SSH agent:

1. `ssh-keygen` checks if the public key file's private half is in `SSH_AUTH_SOCK`
2. If found, signing proceeds using the agent
3. If not found, signing fails with "key not found" error

This is the **core mechanism** that enables SSH agent forwarding for git signing.

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐

```

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Wrapper script for ssh-keygen | Custom shell script | Direct ssh-keygen config | Git handles parameter passing correctly |
| Custom key discovery | Script to find key | ssh-keygen + SSH_AUTH_SOCK | Built-in agent protocol handles this |
| Manual signature format | Custom signature encoding | ssh-keygen -Y sign output | Signature format is cryptographic standard |
| Fallback signing logic | Try multiple signers | Direct failure | Simpler: fail fast, user fixes agent |

**Key insight:** `ssh-keygen -Y sign` already handles everything - git just needs to be configured with the signer path and key file.

## Common Pitfalls

### Pitfall 1: SSH_AUTH_SOCK Not Forwarded
**What goes wrong:** Git signing fails because ssh-keygen cannot find the private key
**Why it happens:** SSH connection didn't forward agent, or agent socket path is invalid
**How to avoid:**
- Verify `ForwardAgent yes` in macOS SSH config for NixOS host
- Verify `AllowAgentForwarding yes` in NixOS sshd_config
**Warning signs:** `ssh-add -L` returns "Could not open a connection to your authentication agent"

### Pitfall 2: Key Mismatch Between Config and Agent
**What goes wrong:** The public key in `signing.key` doesn't match what's in SSH agent
**Why it happens:** Different keys used for allowedSignersFile vs agent
**How to avoid:** Ensure `signing.key` matches the key loaded in 1Password SSH agent
**Warning signs:** Verification fails, signature shows as from unknown signer

### Pitfall 3: allowedSignersFile Path Issues
**What goes wrong:** Git cannot find the allowed signers file
**Why it happens:** Using relative path or file not created properly
**How to avoid:** Use `builtins.toFile` to create file, use `toString` for path
**Warning signs:** `fatal: cannot read allowedSignersFile`

### Pitfall 4: Missing signByDefault Configuration
**What goes wrong:** Commits not signed automatically
**Why it happens:** `signByDefault = true` not set
**How to avoid:** Explicitly configure `programs.git.signing.signByDefault = true`
**Warning signs:** `git log --show-signature` shows no signature
