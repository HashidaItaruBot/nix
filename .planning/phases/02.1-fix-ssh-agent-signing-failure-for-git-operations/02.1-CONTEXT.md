# Phase 02.1: Fix SSH Agent Signing Failure - Context

**Gathered:** 2026-03-19
**Status:** Ready for planning

<domain>
## Phase Boundary

修复 git 使用 SSH agent forwarding 进行签名时的失败问题。Phase 2 已配置 `ssh-keygen` 作为 signer，但需要明确参数细节确保签名正常工作。

</domain>

<decisions>
## Implementation Decisions

### Signer 命令格式
- 只配置 `ssh-keygen` 路径，不指定完整命令字符串
- git 的 `programs.git.signing.signer` 会自动传递必要参数
- 当前配置 `signer = "${pkgs.openssh}/bin/ssh-keygen"` 已正确

### 公钥文件路径
- `ssh-keygen -Y sign` 的 `-f` 参数使用 `~/.ssh/id_ed25519.pub`
- 使用标准路径，git 会自动处理
- 不需要硬编码密钥内容

### 诊断与验证
- 不添加额外的诊断 hooks 或脚本
- 依赖 `ssh-keygen` 失败时的错误信息进行诊断
- 用户可手动运行 `ssh-add -L` 验证 agent forwarding

### 错误处理策略
- 签名失败时直接退出，不回退到其他签名方式
- 保持 Phase 2 决策：NixOS 上不使用 op-ssh-sign
- 错误场景：SSH_AUTH_SOCK 不可用、密钥不匹配

### Claude's Discretion
- 具体参数传递机制（git 内部处理）
- 错误消息的具体内容

</decisions>
